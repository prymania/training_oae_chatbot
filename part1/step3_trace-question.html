เช็คคำถาม → เสริมข้อมูลจาก API → ค้นหาข้อมูลจากเอกสาร → สร้างคำตอบ ( canned / streamming)
4 จุดที่คำถามทุกข้อต้องผ่านตามหลักการ แต่ "จุดสร้างคำตอบ" ในโค้ดมี 2 ที่ ไม่ใช่ 1 ที่ คือ (TRACE 4 กับ TRACE 5) นี่คือจุดที่ต้องการให้ทำความเข้าใจเส้นทางการตามหาคำตอบของบอท

ทำไมต้องมี TRACE 5 แยกจาก TRACE 4

generate_answer() (TRACE 4) ถูกเรียกเฉพาะตอนคำถามเป็น "canned" (ตอบสำเร็จรูปทันที เช่น ทักทาย) หรือเรียกผ่าน endpoint /chat แบบ JSON ธรรมดา
แต่หน้าแชทจริงที่เปิดใช้งานทุกวัน ใช้ /chat/stream เพื่อให้ตัวอักษรไหลออกมาทีละตัว ซึ่งมีโค้ดเรียก DeepSeek + บันทึก log เขียนแยกไว้ต่างหาก ไม่ได้เรียก generate_answer() เลย ถามคำถามปกติแบบ "ราคาข้าววันนี้เท่าไหร่" ผ่านหน้าแชท จะเห็น TRACE 5 ไม่ใช่ TRACE 4

สิ่งสำคัญที่ต้องรู้ก่อนเริ่ม

โปรเจกต์นี้รันผ่าน Docker และ container ไม่ได้เชื่อมไฟล์โค้ดในเครื่องแบบเรียลไทม์ (ไม่มี bind mount) แปลว่าแก้ไฟล์ .py ในเครื่องแล้ว container จะยังไม่เห็นการเปลี่ยนแปลงจนกว่าจะสั่ง build ใหม่ ทุกครั้งที่แก้โค้ด ต้องรัน docker compose up -d --build app ไม่ใช่แค่ up -d เฉย ๆ
