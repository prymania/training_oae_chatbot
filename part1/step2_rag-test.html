ขั้นที่ 2 ทดสอบ RAG

ระบบรันขึ้นแล้ว — มาพิสูจน์ว่า RAG ทำงานยังไง


ทำครบ 12 ข้อของ "ขั้นที่ 1 เตรียมเครื่องพัฒนา" แล้ว ระบบก็แค่ "รันอยู่" แต่ยังไม่รู้ว่ามันทำงานยังไง ขั้นตอนนี้จะทดสอบการทำงานของบอทโดย
1. เริ่มถามบอทเรื่องที่ยังไม่มีเอกสาร (แมววิเชียรมาศ) ระบบตอบกึ่ง ๆ ปฏิเสธ
2. ฝังเอกสาร เข้าไป ถามซ้ำ บอทตอบได้แล้ว
3. ลบเอกสารนั้นทิ้ง (refresh website หลังลบเอกสาร) ถามซ้ำอีกครั้งเพื่อดูว่ามัน "ลืม" ทันที

ถ้าทำสำเร็จ แปลว่าเราเพิ่งพิสูจน์ว่า ระบบนี้ตอบจากเอกสารจริงที่มีอยู่ ณ ขณะนั้นเท่านั้น ไม่ได้ทายจากความรู้ทั่วไปของ AI ต่อให้เรื่องนั้น AI จะ "รู้จัก" อยู่แล้วก็ตาม

🧰 เตรียมเครื่องพัฒนา (ขั้นที่ 1) 🧪 ทดสอบ RAG (ขั้นที่ 2) · กำลังอ่าน 🧵 ตามรอยคำถาม (ขั้นที่ 3) 💬 สร้างแชทบอท LINE (ขั้นที่ 4) 📗 ภาพรวมระบบ (ขั้นที่ 5)

💡 ทำไมขั้นตอนนี้ถึงสำคัญ

แชทบอท AI ทั่วไปตอบจาก "ความจำ" ที่เรียนรู้มาตอนฝึกโมเดล ซึ่งบางครั้งสร้างข้อมูลที่ไม่มีจริงขึ้นมาเองได้ (เรียกว่า hallucination) — ยอมรับไม่ได้กับข้อมูลราชการที่ต้องอ้างอิงได้จริง

OAE Chatbot แก้ปัญหานี้ด้วยเทคนิคที่เรียกว่า RAG (Retrieval-Augmented Generation): ก่อนตอบทุกครั้ง ระบบจะค้นเอกสารที่เกี่ยวข้องก่อน แล้ว กำหนดให้ AI ตอบโดยอ้างอิงจากข้อมูลที่ระบบค้นพบจากฐานความรู้ และหากไม่พบข้อมูลที่เกี่ยวข้อง ระบบจะปฏิเสธการตอบ การทดลองด้านล่างนี้คือการพิสูจน์กลไกนี้แบบจับต้องได้ ไม่ใช่แค่เชื่อคำอธิบาย

ถามคำถามที่ระบบยังไม่รู้จัก

คำถามเกี่ยวกับแมววิเชียรมาศ — ยังไม่ต้องฝังข้อมูลอะไรก่อน
🎯ทำไมต้องเป็นเรื่องแมว: เอกสารของ สศก. เป็นข้อมูลด้านเศรษฐกิจการเกษตรเท่านั้น เรื่องแมว (ปศุสัตว์/สัตว์เลี้ยง) จึงอยู่นอกขอบเขตของฐานความรู้ปัจจุบันโดยสิ้นเชิง — ต่างจากการแต่งข้อมูลปลอมขึ้นมาเอง ตรงที่นี่เป็น "เรื่องจริงที่ AI น่าจะรู้อยู่แล้ว" แต่ระบบต้องปฏิเสธตอบเพราะไม่มีในเอกสารที่มอบให้ ถ้าฝัง cat.txt เข้าไปแล้วบอทตอบถูกได้ แปลว่าคำตอบนั้นมาจากเอกสารที่เพิ่งฝังจริง ๆ ไม่ใช่ความรู้ทั่วไปที่ AI มีอยู่แล้ว
แมววิเชียรมาศมีลักษณะยังไง
ดูแลแมวยังไง
คนไทยมีความเชื่อเกี่ยวกับแมววิเชียรมาศยังไง
💡 สังเกต: ลองถามคำถามพวกนี้ในหน้าแชทตอนนี้เลยก็ได้ — ระบบยังตอบเรื่องแมวไม่ได้ (จะได้คำตอบทำนอง "ไม่มีข้อมูลเรื่องนี้ในเอกสารของ สศก. แนะนำให้ติดต่อกรมปศุสัตว์แทน") เดี๋ยวขั้นถัดไปจะฝังข้อมูลเข้าไป แล้วมาดูว่าคำตอบเปลี่ยนไหม
2

ฝังข้อความเข้าคลังความรู้ (ไม่ต้องมี PDF)

หน้าแอดมิน → แท็บ "โดเมน" → "เพิ่มโดเมน" → แมว, รหัสโดเมน cat
หน้าแอดมิน → แท็บ "ฐานความรู้" → ช่องเพิ่มข้อความโดยตรง
📄เนื้อหาที่จะฝัง: เปิดไฟล์ resource/cat.txt ที่ผู้จัดอบรมเตรียมไว้ (คลิกลิงก์นี้เพื่อเปิด) คัดลอกเนื้อหาทั้งหมด แล้ววางในช่องฝังข้อความโดยตรงที่หน้าแอดมิน
** อย่าลืมเปลี่ยนโดเมน เป็น แมว **
📦ทำอะไร: แท็บ "ฐานความรู้" มี 2 วิธีป้อนข้อมูล — อัปโหลด PDF (ต้องผ่าน OCR ก่อน ใช้เวลานานกว่า) กับ ฝังข้อความโดยตรง (พิมพ์/วางข้อความแล้วฝังทันที ไม่ต้องมีไฟล์เลย) เลือกแบบหลังสำหรับการทดสอบนี้ — เร็วกว่าและตัดตัวแปรเรื่อง OCR ออกไปก่อน
🔧เบื้องหลังที่เกิดขึ้น: ข้อความที่วางเข้าไปจะถูกแปลงเป็น "เวกเตอร์" (ชุดตัวเลขที่แทนความหมาย) ด้วยโมเดล bge-m3 ที่ Ollama รันอยู่ในเครื่องคุณ แล้วบันทึกลงฐานข้อมูล PostgreSQL — เวกเตอร์นี้คือสิ่งที่ระบบใช้ "ค้นหา" ว่าข้อความไหนเกี่ยวข้องกับคำถามที่ถามเข้ามา
🏷️ช่องหมวด/โดเมน: เลือกหมวดอะไรก็ได้ที่มีอยู่แล้วในลิสต์ — ไม่ต้องกังวลว่าไม่มีหมวด "แมว" ให้เลือก เพราะการค้นหาจากหน้าแชทหลักในขั้นที่ 3 ไม่ได้ระบุหมวดเจาะจง (ค้นข้ามหมวดทั้งหมด) เลือกหมวดไหนก็ยังเจอได้เหมือนกัน
✅ เช็ค: กดฝัง/บันทึกแล้วไม่มี error ขึ้น

โบนัส (ไม่บังคับ) — เช็คข้อมูลใน database ที่เราเพิ่งใส่เรื่องแมวลงไป

ลองได้ถ้าอยากเห็นเบื้องหลัง ไม่ทำก็ข้ามไปขั้นที่ 3 ได้เลย
💡ทำไมอยากลอง: ข้อความที่เพิ่งฝังในขั้นที่ 2 ถูกเก็บเป็นแถวหนึ่งในตาราง knowledge_base จริง ๆ ลองเข้าไปดูด้วยตาตัวเองว่าหน้าตาเป็นยังไง มีคอลัมน์อะไรบ้าง
🖥️วิธีที่ 1 — ผ่าน terminal (ไม่ต้องติดตั้งอะไรเพิ่ม): รันจากโฟลเดอร์โปรเจกต์ (chatbot-OAE) — psql ติดมากับ container ของ Postgres อยู่แล้ว
docker compose exec postgres psql -U postgres -d postgres
SELECT id, source, category, left(text, 80) AS text_preview
FROM knowledge_base
ORDER BY id DESC
LIMIT 5;
📦ทำอะไร: คำสั่ง SQL ด้านบนดึงแถวล่าสุด 5 แถวจากตาราง knowledge_base มาโชว์แค่ 80 ตัวอักษรแรกของข้อความ (ตัดคอลัมน์ embedding ที่เป็นตัวเลขยาวเป็นพันตัวออกไปเพื่อให้อ่านง่าย) — พิมพ์ \q แล้ว Enter เพื่อออกจาก psql
🖼️วิธีที่ 2 — ผ่านโปรแกรม DBeaver (ถ้าอยากได้หน้าตา GUI): ดาวน์โหลด DBeaver Community (ฟรี) จาก dbeaver.io/download แล้วสร้างการเชื่อมต่อใหม่แบบ PostgreSQL ด้วยค่าด้านล่าง
Host: localhost
Port: 5433
Database: postgres
Username: postgres
Password: postgres
🎯ทำไม port 5433 ไม่ใช่ 5432: docker-compose.yml จับคู่พอร์ตฝั่งเครื่องเราไว้ที่ 5433 (ไม่ใช่ 5432 มาตรฐาน) เพื่อไม่ให้ชนกับ Postgres ที่อาจติดตั้งไว้ในเครื่องอยู่แล้ว — เชื่อมต่อจากเครื่องเราต้องใช้ 5433 เสมอ (ภายใน container ยังคุยกันที่ 5432 ตามปกติ)
✅ เช็ค: เห็นแถวข้อมูลเรื่องแมววิเชียรมาศที่เพิ่งฝังไปในขั้นที่ 2 (ไม่ว่าจะดูผ่าน psql หรือ DBeaver)

เปิดดู "เส้นทางคำตอบ"

ในหน้าแชท คลิกที่ข้อความคำตอบเพื่อขยาย
🔍 ทำอะไร: คำตอบทุกข้อความในแชทมีปุ่ม/ส่วนขยาย "เส้นทางคำตอบ" ให้กดดู — จะเห็นข้อความต้นฉบับหรือ chunk ที่ระบบค้นพบและนำมาใช้เป็นบริบท ในการสร้างคำตอบ ซึ่งควรตรงกับข้อมูลที่ฝังไว้ในขั้นที่ 2 (จาก cat.txt)

💡 คำตอบที่ควรอธิบายได้

ก่อนเพิ่ม cat.txt ระบบค้นข้อมูลเกี่ยวกับแมวไม่พบ จึงปฏิเสธการตอบ

เมื่อเพิ่ม cat.txt เข้า Knowledge Base ระบบสามารถค้นพบข้อมูลที่เกี่ยวข้องและนำข้อมูลนั้นไปเป็นบริบท ให้ LLM สร้างคำตอบ

เมื่อเราลบ cat.txt ออก แล้วถามคำถามเดิมอีกครั้ง ระบบไม่สามารถค้นพบข้อมูลนั้นได้ และกลับมาปฏิเสธการตอบ

ดังนั้นการทดลองนี้แสดงให้เห็นว่า ผลลัพธ์ของระบบขึ้นอยู่กับข้อมูลที่มีอยู่ใน Knowledge Base และกลไก Retrieval/No-data guard ไม่ได้ปล่อยให้ LLM ตอบจากความรู้ทั่วไปเพียงอย่างเดียว

ทำเสร็จครบแล้ว — ต่อไปคือขั้นที่ 3

ขั้นต่อไปคือ "ตามรอยคำถาม 1 ข้อในโค้ดจริง" — ใส่ print() ของตัวเองตามจุดสำคัญในโค้ด แล้วดู log จริงตอนถามคำถาม อยู่ใน ขั้นที่ 3 — ตามรอยคำถาม
