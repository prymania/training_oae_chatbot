🧰 เตรียมเครื่องพัฒนา (ขั้นที่ 1) · กำลังอ่าน 🧪 ทดสอบ RAG (ขั้นที่ 2) 🧵 ตามรอยคำถาม (ขั้นที่ 3) 📗 ภาพรวมระบบ (ขั้นที่ 4)

-d (detached) ให้โปรแกรมทำงานอยู่เบื้องหลัง ปิดหน้าต่าง terminal ได้โดยโปรแกรมยังทำงานต่อ

เปิด Windows Subsystem for Linux (WSL2)

เปิด PowerShell แบบ Administrator ก่อน (คลิกขวาที่ PowerShell → Run as administrator) 
wsl --install
📦 คำสั่งนี้ทำอะไร: WSL คือฟีเจอร์ของ Windows ที่ช่วยให้เรารัน Linux อยู่ภายใน Windows ได้ คำสั่งนี้จะเปิดใช้งาน WSL และติดตั้ง Ubuntu ให้ด้วย
🎯 ทำไมต้องใช้: Docker Desktop บน Windows ใช้ WSL2 เป็นสภาพแวดล้อม Linux เบื้องหลังสำหรับรัน container ดังนั้นเราต้องเตรียม WSL2 ให้พร้อมก่อนใช้งาน Docker
✅ เช็คว่าสำเร็จ: หลังติดตั้งเสร็จให้ restart เครื่อง 1 ครั้ง จากนั้นเปิด PowerShell ใหม่ แล้วพิมพ์ wsl --status ถ้าไม่ขึ้น error เกี่ยวกับ WSL แสดงว่าพร้อมใช้งานแล้ว

ติดตั้ง Git

โปรแกรม: Git — เครื่องมือจัดการเวอร์ชันของโค้ด
winget install --id Git.Git -e
📦 ลงอะไร: Git คือเครื่องมือสำหรับเก็บประวัติการแก้ไขโค้ด ทำให้เราย้อนกลับไปดูเวอร์ชันก่อนหน้าได้ และช่วยให้หลายคนทำงานกับโค้ดชุดเดียวกันได้โดยไม่ทับงานกัน
🎯 ทำไมต้องใช้: ซอร์สโค้ดของ OAE Chatbot อยู่บน GitHub เราจึงต้องใช้ Git เพื่อดึงโปรเจกต์ลงมาไว้ในเครื่อง และใช้บันทึกการแก้ไขของเราด้วย commit
✅ เช็ค: พิมพ์ git --version แล้วต้องเห็นหมายเลขเวอร์ชัน

ติดตั้ง Node.js LTS

โปรแกรม: Node.js — ใช้รัน JavaScript/TypeScript
winget install --id OpenJS.NodeJS.LTS -e
📦 ลงอะไร: Node.js คือสภาพแวดล้อมที่ทำให้ JavaScript/TypeScript สามารถรันนอกเบราว์เซอร์ได้ และติดตั้ง npm ซึ่งเป็นตัวจัดการแพ็กเกจมาด้วย โดยเราเลือกใช้รุ่น LTS ซึ่งเป็นรุ่นที่เน้นความเสถียรและมีการสนับสนุนระยะยาว
🎯 ทำไมต้องใช้: ส่วนหน้าเว็บของ OAE Chatbot ใช้ React + TypeScript จึงต้องใช้ Node.js และ npm สำหรับติดตั้งไลบรารีและ build หน้าเว็บ
✅ เช็ค: node --version และ npm --version ต้องแสดงหมายเลขเวอร์ชันทั้งคู่

ติดตั้ง Docker Desktop

โปรแกรม: Docker Desktop — ใช้จัดการ container ของระบบ
winget install --id Docker.DockerDesktop -e
📦 ลงอะไร: Docker Desktop คือโปรแกรมสำหรับสร้างและจัดการ container ซึ่งเป็นเหมือนกล่องที่รวมโปรแกรมและสิ่งที่โปรแกรมต้องใช้ไว้ด้วยกัน ทำให้โปรเจกต์เดียวกันสามารถรันบนเครื่องของแต่ละคนได้ใกล้เคียงกันมาก
🎯 ทำไมต้องใช้: OAE Chatbot เตรียมไฟล์ Docker Compose ไว้ให้แล้ว เราจึงสามารถสั่งเปิดระบบหลายส่วนพร้อมกันได้ด้วยคำสั่งเดียว เช่น FastAPI, PostgreSQL + pgvector และ Ollama ไม่ต้องติดตั้งและตั้งค่าแต่ละส่วนแยกกันเอง
✅ เช็ค: หลังติดตั้งเสร็จ ให้เปิด Docker Desktop ขึ้นมาอย่างน้อย 1 ครั้ง และรอจน Docker พร้อมใช้งาน จากนั้นลองพิมพ์ docker --version ใน terminal

ติดตั้ง uv

โปรแกรม: uv — ใช้จัดการ Python และแพ็กเกจของโปรเจกต์
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
📦 ลงอะไร: uv คือเครื่องมือสำหรับจัดการ Python, แพ็กเกจ และสภาพแวดล้อมของโปรเจกต์ ทำหน้าที่หลายอย่างที่เดิมเราอาจต้องใช้ pip และ venv หลายตัวร่วมกัน และทำงานได้เร็วมาก
🎯 ทำไมต้องใช้: Backend ของ OAE Chatbot เขียนด้วย Python และใช้ FastAPI คำสั่งสำหรับรันเซิร์ฟเวอร์ รวมถึงคำสั่งสำหรับติดตั้งแพ็กเกจ และรันสคริปต์ต่าง ๆ ของโปรเจกต์ ใช้ uv เป็นตัวจัดการ
💡 ทำไมไม่ใช้ winget: สำหรับการอบรมนี้ เราติดตั้ง uv ผ่านสคริปต์ติดตั้งของผู้พัฒนาโดยตรง คำสั่งด้านบนจะดาวน์โหลดและติดตั้ง uv ให้โดยอัตโนมัติ
✅ เช็ค: พิมพ์ uv --version แล้วต้องเห็นหมายเลขเวอร์ชัน ถ้ายังไม่เจอ ให้ลองปิดแล้วเปิด terminal ใหม่ในขั้นตอนถัดไป

สร้างไฟล์ตั้งค่า .env

ใส่ API Key และค่าตั้งค่าที่ใช้เฉพาะเครื่องนี้
copy .env.example .env
📦 ทำอะไร: .env.example เป็นไฟล์ตัวอย่างที่เตรียมค่าไว้ให้ แต่ไม่มี API Key จริง คำสั่ง copy จะสร้างไฟล์ .env จากไฟล์ตัวอย่าง จากนั้น เปิดไฟล์ .env เพื่อแก้ไขข้อมูล
🎯 ต้องกรอกอะไร: คัดลอกค่าด้านล่างไปใส่ในไฟล์ .env แล้วแทนที่ TYPHOON_API_KEY ด้วย API Key ของตัวเองจากขั้นตอนที่ 1
สำคัญ: ไฟล์ .env ห้าม commit หรือ push ขึ้น GitHub เพราะมี API Key จริงอยู่ข้างใน 
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin1234
TYPHOON_API_KEY= (API Key ของผู้เข้าอบรม)
DEEPSEEK_API_KEY=sk-0f77d39006ac487b904cb26537551438
หมายเหตุสำคัญ

DEEPSEEK_API_KEY ด้านบนเป็น กุญแจชั่วคราวสำหรับการอบรมเท่านั้น ไม่ใช่กุญแจสำหรับระบบจริง
TYPHOON_API_KEY ให้ใช้ API Key ของตัวเองที่สมัครไว้ในขั้นตอนที่ 1
อย่าลืมลบค่าตัวอย่างเดิม / บรรทัดเดิมของ TYPHOON_API_KEY และ DEEPSEEK_API_KEY ก่อนใส่ค่าของตัวเอง

(1) ใช้สำหรับเริ่มระบบครั้งแรก — ตอนเริ่มต้น database อาจยังไม่มีบัญชีผู้ใช้ ระบบจึงต้องมีบัญชีสำหรับเริ่มต้นเข้าไปจัดการระบบ
(2) ใช้เป็นทางเข้าสำรอง — หากบัญชีใน database มีปัญหา ค่าใน .env ยังสามารถใช้เป็นข้อมูลสำรองสำหรับเข้าสู่ระบบได้
