Terminal 1 — ฐานข้อมูล

เปิดทิ้งไว้

ถ้าเคยมี container app ค้างพอร์ต 8000 อยู่ ให้หยุดก่อน แล้วเปิดแค่ Postgres:

docker compose stop app
docker compose up -d postgres
รอจนเห็น Container chatbot-oae-postgres-1 Started

Terminal 2 — Backend

เปิดทิ้งไว้

--reload สำคัญมาก — เมื่อมีการแก้ไฟล์ .py แล้ว save จะรีสตาร์ทให้เองอัตโนมัติ :

uv run uvicorn rag_server:app --reload --port 8000
รอจนเห็น Application startup complete

Terminal 3 — Frontend

เปิดทิ้งไว้

ไม่ต้องตั้งตัวแปรอะไรก่อนแล้ว (แก้ vite.config.ts ให้ default ชี้ local อยู่แล้ว) พิมพ์คำสั่งเดียวพอ:

npm install
npm run dev
รอจนเห็น Local: http://localhost:5173/
กฎเดียวที่ต้องจำ

ตลอดคาบ เปิดแค่ http://localhost:5173 เท่านั้นในเบราว์เซอร์ — ห้ามเปิด localhost:8000 ดูเว็บเด็ดขาด (8000 เปิดดูเฉพาะตอนอยากเช็ค API ผ่าน Swagger ที่ /docs เท่านั้น ดูหัวข้อ 5)

แก้โค้ดแล้ว ต้อง restart อะไรไหม

แก้อะไรต้อง restart ไหม
ไฟล์ frontend (.tsx / .ts / .css)❌ ไม่ต้อง — hot reload อัตโนมัติ แค่ save แล้วดูที่ 5173
ไฟล์ backend (.py)❌ ไม่ต้อง — มี --reload อยู่แล้ว แค่ save รอ 2-3 วินาที
ไฟล์ .env✅ ต้อง — กด Ctrl+C ที่ Terminal 2 แล้วรันคำสั่ง backend ใหม่ (env โหลดตอนสตาร์ทครั้งเดียวเท่านั้น)
Docker (Postgres)❌ ไม่ต้องแตะเลยทั้งคาบ
ถ้า backend error ตอนสตาร์ท เรื่อง .env

ถ้าเจอ error แบบ ValueError: invalid literal for int() ตอนรัน Terminal 2 — สาเหตุมักมาจากไฟล์ .env มีบรรทัด KEY= เว้นว่างไว้โดยไม่มี # นำหน้า ให้ comment ทั้งบรรทัดด้วย # ถ้ายังไม่อยากตั้งค่านั้น (รายละเอียดเต็มดูที่ explain.html)

Gotcha สำคัญ

Route handler ต้องเป็น def ธรรมดา ไม่ใช่ async def เว้นแต่จะ await อะไรจริง ๆ — เพราะ DB call (psycopg2) และ LLM call (OpenAI/ollama client) เป็น blocking call ทั้งหมด ถ้าใช้ async def เฉย ๆ จะ freeze ทั้ง process เวลามีหลาย request พร้อมกัน (ดู "Concurrency model" ใน AGENTS.md)

vite.config.ts

server.proxy ใน vite.config.ts ผูก path API ทั้งหมด (/chat, /auth, /admin/... ฯลฯ) เข้ากับตัวแปร VITE_PROXY_TARGET — เดิมค่า default ชี้ไป production VPS จริง ทำให้ dev บางครั้งเห็นข้อมูล production ปนกับ local โดยไม่รู้ตัว ตอนนี้แก้ default ให้ชี้ localhost:8000 แล้ว จึงไม่ต้องตั้งตัวแปรอะไรก่อน npm run dev อีกต่อไป

ถ้าอยาก override เอง (ไม่จำเป็นสำหรับวันอบรม)

$env:VITE_PROXY_TARGET = "https://..."; npm run dev — จำไว้ว่าตัวแปรนี้อ่านจาก shell environment ล้วน ๆ ไม่โหลดจาก .env อัตโนมัติ เหมือนฝั่ง Python ต้องตั้งใหม่ทุกครั้งที่เปิด terminal ใหม่

Swagger / API Docs

FastAPI สร้าง Swagger ให้อัตโนมัติ ไม่ต้องเขียนเอง — แต่มีจุดที่ต้องระวังเรื่อง URL

ต้องเข้าที่พอร์ต backend (8000) เท่านั้น

http://localhost:5173/docs จะไม่ใช่ Swagger จริง — Vite dev server ไม่มี proxy rule สำหรับ /docs เลยได้แค่หน้า React app เปล่า ๆ (SPA fallback) กลับมา ต้องเปิด http://localhost:8000/docs ตรง ๆ เสมอ (ทดสอบแล้ว: 8000 ได้ Swagger UI จริง ส่วน 5173 ได้แค่ HTML shell ของ React)

GET /docs
Swagger UI แบบโต้ตอบได้ — ลองยิง endpoint จริงจากหน้าเว็บได้เลย (มี "Try it out") — ใช้ทดสอบการแก้ backend text ได้โดยไม่ต้องพึ่ง frontend
ใช้ localhost:8000 เท่านั้น
GET /redoc
เอกสารแบบอ่านอย่างเดียว จัดหมวดสวยกว่า เหมาะเวลาจะพิมพ์ให้คนอื่นอ่าน
ใช้ localhost:8000 เท่านั้น
GET /openapi.json
OpenAPI schema ดิบ — เอาไป generate client code หรือ import เข้า Postman/Insomnia ได้
GET /api-docs
หน้า React ที่เขียนเอง (ไม่ใช่ Swagger) — โฟกัสเฉพาะ /api/v1/* อธิบาย envelope format ให้หน่วยงานภายนอกอ่าน
# เช็คว่า backend รันอยู่ก่อนเปิด Swagger
curl http://localhost:8000/health

# เปิด Swagger ในเบราว์เซอร์
start http://localhost:8000/docs
Endpoint ที่ต้อง login ก่อนถึงจะลองใน Swagger ได้

/admin/* ต้องมี JWT token ของ admin (login ผ่าน POST /admin/login ก่อน แล้วเอา token มาใส่ปุ่ม "Authorize" มุมขวาบนของ Swagger UI) ส่วน POST /api/v1/rag/query ต้องมี header X-API-Key จาก API_V1_KEYS ใน .env

วิธีทำงาน: เปิด npm run dev (ไม่ต้องสนใจ VITE_PROXY_TARGET เลยสำหรับโจทย์กลุ่มนี้ เพราะเป็นข้อความล้วน ไม่มีการเรียก backend) → แก้ไฟล์ → save → เห็นผลที่ localhost:5173 ทันทีด้วย hot reload — ปลอดภัย ไม่มี backend เกี่ยวข้อง เหมาะเป็นโจทย์อุ่นเครื่องก่อน

7.2 Backend — แก้ข้อความ/พฤติกรรม, เห็นผลด้วย Swagger

โจทย์ไฟล์ตัวแปร
ข้อความทักทายapp/services/intent_router.py:92_GREETING_REPLY
ข้อความกรณีไม่เจอคำตอบapp/services/intent_router.py:108_NO_DATA_REPLY
รูปแบบการตอบ (bullet, การอ้างอิง, โทนเสียง)app/config.py:250SYSTEM_PROMPT
ชื่อบอท/บุคลิกSYSTEM_PROMPT เดียวกันค้นหาคำว่า "สศก Chatbot"
ความยาวคำตอบapp/config.py:61DEEPSEEK_MAX_TOKENS_CONCISE (ลอง 300 vs 1500 เทียบกัน)
เปิด/ปิดการจัดลำดับผลลัพธ์ใหม่app/config.pyRAG_RERANK_ENABLED = True/False — เห็นผลต่างชัดถ้าถามคำถามในโดเมนที่มีข้อมูลซ้อนกันหลายปี

วิธีทำงาน (แนะนำสำหรับห้องอบรม 10 คน):

  1. รัน backend ด้วย uv run uvicorn rag_server:app --reload --port 8000 (--reload สำคัญ — แก้ .py แล้ว server รีสตาร์ทเองอัตโนมัติ ไม่ต้องกด Ctrl+C เอง)
  2. แก้ไฟล์ตามตารางข้างบน → save → รอ terminal reload เสร็จ (ไม่กี่วินาที)
  3. เปิด localhost:8000/docs → หา POST /chat → กด "Try it out" → ใส่ {"message": "สวัสดี"} (ทดสอบทักทาย) หรือคำถามนอกโดเมนที่มี เช่น "ราคาปลา" (ทดสอบ no-data reply เพราะ local KB มีแค่ chicken/palm_oil/swine) → Execute → เห็นข้อความที่แก้ตรง ๆ ในผลลัพธ์ ไม่ต้องพึ่ง frontend เลย
✨

7.3 โจทย์เสริม (ถ้าเวลาเหลือ)

  • ปรับ TOP_K (app/config.py) จาก 10 → 3 แล้วดูว่าคำตอบสั้น/แคบลงไหม (ทำให้เห็นผลของ RAG parameter ชัดเจน)
  • ปิด INTENT_ROUTER_ENABLED ชั่วคราว แล้วลองพิมพ์ "สวัสดี" อีกครั้ง — จะเห็นว่าคำตอบเปลี่ยนจาก canned reply เป็นไป RAG เต็มรูปแบบแทน (สอนให้เห็นว่า flag ตัวนี้ทำอะไร)
