เข้าใจค่า Local vs Production
OAE Chatbot — ทำไม frontend ที่รันในเครื่อง ถึงบางทีคุยกับ production จริง
← หน้าหลัก
อ้างอิงประกอบการรัน local

ทำไม database local ดูมีข้อมูลเยอะเหมือน production ทั้งที่เพิ่งตั้งเครื่องเอง

สรุปจากคำถามจริงที่เจอ: รัน npm run dev แล้วเข้าหน้าเว็บ เห็นข้อมูลหมวดหมู่เยอะผิดปกติ (30,000+ รายการ) ทั้งที่ database ในเครื่องมีแค่ไม่กี่สิบแถว — สาเหตุคือมี "จุดตั้งค่า" หลายจุดที่แยกกันคนละไฟล์ คนละกลไก เอกสารนี้ไล่ทีละไฟล์ ทีละคำสั่ง ให้เข้าใจว่าต้องดูตรงไหน และเช็คยังไงให้มั่นใจ ไม่ต้องเดา

อาการที่เจอ

เปิดหน้าเว็บที่ localhost:5173 แล้วเห็นหมวดหมู่ความรู้เยอะผิดปกติ (เช่น "งบประมาณ", "รายงานประจำปี") ทั้งที่เพิ่งตั้ง database ในเครื่องเอง ยังไม่ได้ ingest ข้อมูลอะไรเข้าไปเลย

สาเหตุที่แท้จริง

Frontend dev server (5173) ไม่ได้คุยกับ backend local (8000) แต่ proxy ไปคุยกับ backend production จริง เพราะไม่ได้ตั้งค่าตัวแปรตัวหนึ่งก่อนรัน npm run dev — ค่า default ในโค้ดจะ fallback ไปที่เซิร์ฟเวอร์จริงทันที

🐍 Backend (Python)

  • อ่านค่าจาก app/config.py
  • โหลดไฟล์ .env ให้ อัตโนมัติ
  • แพทเทิร์น: os.environ.get("KEY", default)

⚡ Frontend (Vite/Node)

  • อ่านค่าจาก vite.config.ts
  • ไม่โหลด .env ให้อัตโนมัติ
  • แพทเทิร์น: process.env.KEY || default
  • ต้องตั้งเป็น shell env var เองทุกครั้ง
ฝั่ง Backend
1

เปิด app/config.py ดูแพทเทิร์นการอ่านค่า

ไฟล์: app/config.py

ทุกตัวแปรในไฟล์นี้ใช้แพทเทิร์นเดียวกันหมด จำรูปแบบนี้ไว้แล้วอ่านโค้ดที่เหลือได้เอง:

DATABASE_URL = os.environ.get(
    "DATABASE_URL", "postgresql://postgres:postgres@localhost:5433/postgres"
)
OLLAMA_HOST = os.environ.get("OLLAMA_HOST", "http://localhost:11434")
🔑 วิธีอ่าน: os.environ.get("ชื่อตัวแปร", "ค่า default") — ถ้ามีใครตั้งค่าตัวแปรนี้ไว้ (จาก .env หรือ shell) จะใช้ค่านั้น ถ้าไม่มีใครตั้งเลย จะใช้ค่าตัวที่สองในวงเล็บเป็น default
2

เปิดไฟล์ .env ที่ root โปรเจกต์

ไฟล์: .env (ไม่ใช่ .env.example)

กฎ 2 ข้อที่ต้องจำ:

✅ บรรทัดที่ไม่มี # นำหน้า + มีค่าจริงหลัง = ค่านี้ "ชนะ" default ใน config.py เพราะ config.py เรียก load_dotenv(override=True) — override=True แปลว่า .env ชนะแม้แต่ค่าที่อาจตั้งไว้ในเครื่อง (Windows environment variables) ด้วย
⛔ บรรทัดที่ขึ้นต้นด้วย # เท่ากับไม่มีบรรทัดนั้นเลย → config.py fallback ไปใช้ default ของตัวเอง
กับดักที่เจอมาแล้ว

เขียน KEY=    # คำอธิบาย (เว้นค่าว่างแต่มีคอมเมนต์ต่อท้าย) — python-dotenv จะอ่านทั้ง # คำอธิบาย เป็นค่าจริงของตัวแปรนั้นไปเลย ไม่ใช่ค่าว่าง! ถ้าตัวแปรนั้นถูกเอาไป int(...) ต่อ โปรแกรมจะ crash ทันที วิธีที่ถูกต้องถ้ายังไม่อยากตั้งค่า คือ comment ทิ้งทั้งบรรทัดด้วย # นำหน้าเลย ไม่ใช่เว้นแค่ค่า

3

เช็คค่าจริงที่ backend ใช้ (ไม่ต้องเดา)

คำสั่ง: uv run python -c "..."

อย่าเดาจากการอ่านโค้ดอย่างเดียว ให้รันคำสั่งนี้เพื่อดูค่าที่ "คำนวณเสร็จแล้ว" จริง ๆ:

uv run python -c "from app import config; print(config.DATABASE_URL); print(config.OLLAMA_HOST)"
ผลลัพธ์ที่ได้ = ค่าจริงที่ rag_server.py จะใช้ตอนสตาร์ท ไม่ใช่การอ่านโค้ดแล้วเดาเอา
ฝั่ง Frontend — จุดต่างสำคัญ
4

เปิด vite.config.ts ดูแพทเทิร์นฝั่ง frontend

ไฟล์: vite.config.ts
"/chat": {
  target: process.env.VITE_PROXY_TARGET || "http://151.246.242.116:8818",
  changeOrigin: true,
},
ต่างจาก backend ตรงนี้

process.env.VITE_PROXY_TARGET อ่านจาก Windows/shell environment variable ล้วน ๆ — ไม่มีโค้ดตรงไหนใน vite.config.ts โหลดไฟล์ .env เลย ต่อให้เขียน VITE_PROXY_TARGET=http://localhost:8000 ลงใน .env ก็ ไม่มีผลกับไฟล์นี้เลย

ถ้าไม่ตั้งตัวแปรนี้ก่อนรัน npm run dev → ทุก request (/chat, /admin/..., /categories ฯลฯ) จะยิงตรงไปที่ http://151.246.242.116:8818 ซึ่งคือ production VPS จริง ทันที — นี่คือรากของปัญหาที่เจอ

5

เช็คว่า terminal ที่รัน npm run dev อยู่ ตั้งค่านี้หรือยัง

คำสั่ง: echo $env:VITE_PROXY_TARGET

ไปที่ terminal เดิมที่รัน npm run dev ค้างอยู่ (หรือเทอร์มินัลที่ใช้สั่งตอนนั้น) พิมพ์:

echo $env:VITE_PROXY_TARGET
⛔ ว่างเปล่า → process ที่รันอยู่ไม่ได้ตั้งค่านี้ → กำลังคุยกับ production แน่นอน
✅ มีค่า http://localhost:8000 → ตั้งไว้แล้ว ถูกต้อง
ข้อควรรู้

ตัวแปรนี้อยู่แค่ใน session ของ terminal นั้น เท่านั้น ปิด terminal แล้วเปิดใหม่ ค่านี้หายไปเลย ต้องตั้งใหม่ทุกครั้งที่เปิด terminal ใหม่มารัน npm run dev

6

verify แบบไม่ต้องพึ่งความจำ — เทียบ response จริง

คำสั่ง: curl (ยิงตรง vs ผ่าน proxy)

วิธีนี้ใช้ได้เสมอไม่ว่าจะสงสัยเรื่องอะไร — เทียบ backend ตรง ๆ กับที่ผ่าน frontend proxy:

curl http://localhost:8000/categories
curl http://localhost:5173/categories
✅ ผลลัพธ์เหมือนกัน → frontend กำลังคุยกับ local backend ถูกต้องแล้ว
⛔ ผลลัพธ์ต่างกัน → frontend (5173) กำลังคุยกับ production อยู่ ยังไม่ได้ตั้งค่า proxy ให้ถูก
7

แก้ปัญหา — ตั้งค่าให้ถูกก่อนรัน dev server

ต้องทำใน terminal เดียวกับที่จะรัน npm run dev

1. ไป terminal ที่รัน npm run dev ค้างอยู่ กด Ctrl+C เพื่อหยุดก่อน
2. พิมพ์ตั้งค่า แล้วค่อยรันใหม่ (แยกกัน 2 บรรทัด):

$env:VITE_PROXY_TARGET = "http://localhost:8000"
npm run dev

3. กลับไปทำ ขั้น 5 และ ขั้น 6 ซ้ำอีกรอบ เพื่อยืนยันว่าตั้งถูกแล้ว

📌 สรุปสั้น ๆ ไว้ทวนภายหลัง

อยากรู้อะไรดูไฟล์ไหนวิธี verify
backend ใช้ DB/Ollama ตัวไหน .env + app/config.py uv run python -c "from app import config; print(config.DATABASE_URL)"
frontend proxy ไปหา backend ตัวไหน vite.config.ts echo $env:VITE_PROXY_TARGET ใน terminal ที่รัน npm run dev
ตอนนี้กำลังคุยกับ local หรือ production จริง — เทียบ curl localhost:8000/categories กับ curl localhost:5173/categories
สร้างจากคำถาม/คำอธิบายจริงระหว่างเซสชันแก้ไฟล์ .env และไล่หา proxy target ของโปรเจกต์ OAE Chatbot
