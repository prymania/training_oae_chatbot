คู่มือ Deploy ขึ้น Server B (เครื่อง NABC On-Prem) ---------- demp_part4

เอกสารนี้ทำขึ้นเพื่อให้เห็นโฟลว์การอบรมทั้งหมดก่อน — ไม่ใช่คู่มือที่พร้อมสอนจริง 100% เนื้อหาที่ยืนยันได้แล้ว (คำสั่ง Docker, การตรวจสอบระบบ, งานประจำสัปดาห์) มาจากเอกสารโค้ดจริงและสไลด์ deploy guide ของทีมพัฒนา ส่วนที่ยังขาด (วิธีต่อ Cloudflare Tunnel จริง และที่มาของบัญชี nabcadm) ถูกทำเครื่องหมายไว้ชัดเจนเป็นกล่องสีเหลืองทุกจุด — ต้องขอข้อมูลจากฝั่ง NABC ก่อนเอาไปสอนจริงในวันอบรม

สถานะของคู่มือนี้ — อ่านก่อนใช้งาน

⚠ ยังไม่ยืนยัน 2 จุด

1) วิธีต่อเข้า Server B ผ่าน Cloudflare Tunnel จริง ๆ (โปรแกรม/hostname/การตั้งค่าฝั่งเครื่องเจ้าหน้าที่)
2) บัญชี nabcadm ใช้รหัสผ่านหรือกุญแจ SSH เข้า และควรได้รับจากใครในฝั่ง NABC

ทั้งสองจุดนี้ไม่มีอยู่ในเอกสารหรือสไลด์ที่ตรวจสอบได้ — ต้องถามคนที่ตั้ง Server B ไว้ให้ (น่าจะเป็นฝั่ง NABC หรือเพื่อนร่วมทีมที่แนะนำ Cloudflare Tunnel) ดูรายการที่ต้องขอทั้งหมดได้ที่ ภาคผนวก: Checklist ส่งให้ NABC

1

เข้าใจก่อนเริ่ม: Server A ต่างจาก Server B ตรงไหน

โปรเจกต์นี้มี 2 เซิร์ฟเวอร์ที่ deploy คนละวิธีกัน — คู่มือ deploy ฉบับอื่นที่เคยเห็น (แบบ git pull) ใช้กับ Server B ไม่ได้

Server A (Cloud VPS)Server B (NABC On-Prem)
วิธีอัปเดตโค้ดgit pull แล้ว build ใหม่อัปโหลดไฟล์ที่แก้เองผ่าน SFTP ไม่มี git pull
การเข้าถึงเซิร์ฟเวอร์SSH ตรง สิทธิ์ rootผ่าน Cloudflare Tunnel สิทธิ์จำกัดกลุ่ม Docker เท่านั้น
ผู้ใช้บนเซิร์ฟเวอร์rootnabcadm (ไม่มีรหัส sudo)
HTTPS/SSLLet's Encrypt (มีโดเมนสาธารณะ)Cloudflare Tunnel (เครื่อง internal ไม่มีโดเมนสาธารณะ)
งานประจำ (sync ราคา/รายงาน)ตั้ง cron อัตโนมัติครบไม่มี cron — ต้องรันคำสั่งเอง (หัวข้อ 4)
จำไว้ประโยคเดียว

Server A "ดึงโค้ดจาก GitHub เอง" ส่วน Server B "ต้องเอาไฟล์ไปวางเอง" — เจ้าหน้าที่ 2 คนที่ดูแล Server B จึงต้องระวังเรื่อง "อัปโหลดไฟล์ให้ครบ" มากเป็นพิเศษ เพราะไม่มีระบบช่วยดึงให้อัตโนมัติเหมือน Server A

2

สิ่งที่ต้องเตรียมก่อนวันอบรม

ส่วนที่ทำได้เลยตอนนี้ กับส่วนที่ต้องรอข้อมูลจาก NABC ก่อน

รายการสถานะใครจัดการ
เพิ่มเจ้าหน้าที่ 2 คนเข้า GitHub repoทำได้เลยตอนนี้คุณ (เจ้าของโปรเจกต์)
ติดตั้งโปรแกรม SFTP client (เช่น WinSCP หรือ FileZilla — ฟรี) บนเครื่องเจ้าหน้าที่ทำได้เลยตอนนี้เจ้าหน้าที่ 2 คน / ผู้เตรียมเครื่อง
วิธีต่อเข้า Server B ผ่าน Cloudflare Tunnel (โปรแกรม + การตั้งค่า)⚠ ยังไม่ยืนยันต้องขอจาก NABC
บัญชี nabcadm (รหัสผ่านหรือกุญแจ SSH)⚠ ยังไม่ยืนยันต้องขอจาก NABC
3

ขั้นตอน Deploy ประจำวัน (Server B)

ลำดับที่เจ้าหน้าที่ต้องทำทุกครั้งหลังแก้โค้ดเสร็จ — ขั้น B ยังเป็นช่องว่างที่ต้องเติมทีหลัง

ขั้น A — บนเครื่องเจ้าหน้าที่: แก้โค้ดแล้ว push ขึ้น GitHub

แม้ Server B จะไม่ได้ดึงโค้ดจาก GitHub โดยตรง ก็ยังควร push ทุกครั้งอยู่ดี เพื่อเก็บประวัติการแก้ไขไว้ให้คนอื่นตามงานได้ และเผื่อย้อนดูว่าไฟล์ไหนเปลี่ยนไปบ้างก่อนอัปโหลด

git add .
git commit -m "อธิบายสิ่งที่แก้ไข"
git push origin main

ขั้น B — ต่อเข้า Server B ผ่าน Cloudflare Tunnel

⚠ ช่องว่างที่ต้องเติม

ยังไม่มีขั้นตอนยืนยันว่าต้องติดตั้ง/ตั้งค่าโปรแกรมอะไรบนเครื่องเจ้าหน้าที่เพื่อต่อผ่าน Cloudflare Tunnel — รวมถึง hostname หรือลิงก์ที่ใช้เชื่อมต่อ ต้องขอจาก NABC แล้วเติมส่วนนี้ก่อนใช้สอนจริง (ดู checklist)

ขั้น C — อัปโหลดไฟล์ที่แก้ไขผ่าน SFTP

เปิดโปรแกรม SFTP (เช่น WinSCP) เชื่อมต่อไปที่โฟลเดอร์โปรเจกต์บน Server B คือ /home/nabcadm/chatbot-dld แล้วอัปโหลดเฉพาะไฟล์/โฟลเดอร์ที่แก้ไข ทับของเดิมในตำแหน่งเดียวกัน (path ต้องตรงกับที่แก้ในเครื่องตัวเอง)

ห้ามอัปโหลดทับสิ่งเหล่านี้เด็ดขาด
  • .env — เก็บรหัสผ่าน/API key ของจริงบนเซิร์ฟเวอร์ ถ้าทับด้วยไฟล์จากเครื่องตัวเอง (ที่มักไม่มีค่าเหล่านี้) ระบบจะล่มหรือรหัสผ่านเปลี่ยนโดยไม่ตั้งใจ
  • โฟลเดอร์ data/ — เก็บไฟล์ที่ผู้ใช้อัปโหลดจริงและแคช OCR ถ้าทับจะเสียข้อมูลที่สะสมไว้

ขั้น D — สั่ง Docker สร้างระบบใหม่จากไฟล์ที่อัปโหลด

ต่อ SSH เข้า Server B ผ่านช่องทางเดียวกับขั้น B แล้วรันคำสั่งชุดนี้ — ไม่ต้องใช้ sudo เพราะบัญชี nabcadm อยู่ในกลุ่ม Docker ไว้แล้ว

cd /home/nabcadm/chatbot-dld

# แนะนำ: แปะป้ายรุ่นเดิมไว้ก่อน เผื่อต้องย้อนกลับ
docker tag chatbot-dld-app:latest chatbot-dld-app:backup-$(date +%Y%m%d)

# สร้างระบบใหม่จากไฟล์ที่เพิ่งอัปโหลด (เฉพาะ container ของแอป)
docker compose -f docker-compose.prod.yml up -d --build app

# เช็คว่าทุก container ขึ้นสถานะ healthy
docker compose -f docker-compose.prod.yml ps
ข้อควรระวัง

ชื่ออิมเมจ/คอนเทนเนอร์ (chatbot-dld-app) เป็นชื่อที่คาดว่าจะใช้ตามชื่อโฟลเดอร์โปรเจกต์ — ยังไม่ได้ตรวจสอบกับเครื่องจริง ก่อนใช้สอน ให้รัน docker compose -f docker-compose.prod.yml ps ดูชื่อจริงก่อนเสมอ แล้วแก้คำสั่งด้านบนให้ตรง

ขั้น E — ตรวจสอบว่าใช้งานได้จริง

curl http://localhost:8818/health

ต้องเห็น "status": "healthy" และ "database": "connected" จากนั้นเปิดเว็บผ่านลิงก์ Cloudflare Tunnel เพื่อลองถามคำถามจริง 1 ข้อ ดูว่าคำตอบขึ้นพร้อมเลขอ้างอิงแหล่งที่มาปกติหรือไม่

4

งานประจำสัปดาห์ที่ต้องรันเอง (ไม่มี cron)

Server A ตั้งให้รันอัตโนมัติ แต่ Server B ยังไม่มี — ต้องรันคำสั่งเหล่านี้ด้วยมือตามกำหนด (คัดลอกมาจากงาน cron ของ Server A)

งานควรรันตอนไหนคำสั่ง
ซิงก์ราคาสินค้ารายสัปดาห์ทุกสัปดาห์docker exec <ชื่อ container แอป> python scripts/sync_price_facts.py
ซิงก์ข้อมูลผลผลิต (CKAN)ทุกวันจันทร์docker exec <ชื่อ container แอป> python scripts/sync_ckan_production.py
สร้างรายงาน AI ประจำสัปดาห์ทุกวันจันทร์/home/nabcadm/chatbot-dld/scripts/weekly_insights.sh
ข้อควรระวัง

ชื่อ container แอปต้องเช็คจาก docker compose -f docker-compose.prod.yml ps ก่อนรันทุกครั้ง (อาจไม่ใช่ชื่อเดียวกับ Server A) — และควรคุยกับ NABC ว่าจะให้เจ้าหน้าที่รันมือทุกสัปดาห์แบบนี้ไปเรื่อย ๆ หรือควรตั้ง cron ให้ Server B ในอนาคต เพื่อลดงานที่ต้องจำ

5

เมื่อมีปัญหา — เช็กตรงไหนก่อน

อาการวิธีเช็ก/แก้เบื้องต้น
หน้าเว็บไม่เปลี่ยนหลังอัปโหลดไฟล์ใหม่ต้องสั่ง --build ซ้ำเสมอ เพราะไฟล์หน้าเว็บถูกฝังอยู่ใน Docker image ไม่ใช่ไฟล์ที่เสิร์ฟตรง ๆ
Container ขึ้นสถานะ unhealthyดู log ด้วย docker compose -f docker-compose.prod.yml logs --tail=200 app
ตอบคำถามแบบไม่ทยอยขึ้นทีละคำ (ไม่ stream)ปัญหามักอยู่ที่การตั้งค่า Nginx/Cloudflare ฝั่งรับ-ส่งข้อมูล ต้องแจ้ง NABC ตรวจการตั้งค่าฝั่งนั้น
ดิสก์เต็มจากการ build บ่อย ๆdocker builder prune -f ล้างไฟล์ build เก่าที่ไม่ใช้แล้ว
ต้องย้อนกลับเวอร์ชันก่อนหน้าใช้อิมเมจที่แปะป้าย backup-วันที่ ไว้ตอนขั้น D แล้วสั่งรันอิมเมจนั้นแทน โดยไม่แตะ volume ฐานข้อมูล

ภาคผนวก: Checklist ส่งให้ NABC ก่อนวันอบรม

ส่งรายการนี้ให้ฝ่าย NABC หรือเพื่อนที่ตั้ง Server B ไว้ กรอกให้ครบก่อนใช้คู่มือนี้สอนจริง

#สิ่งที่ต้องขอคำตอบ (กรอกทีหลัง)
1โปรแกรมที่ต้องติดตั้งบนเครื่องเจ้าหน้าที่เพื่อต่อผ่าน Cloudflare Tunnel คืออะไร (เช่น cloudflared) และดาวน์โหลด/ตั้งค่าอย่างไร—
2hostname หรือคำสั่งที่ใช้เชื่อมต่อจริง (สำหรับทั้ง SFTP และ SSH)—
3บัญชี nabcadm ใช้รหัสผ่านหรือกุญแจ SSH เข้า และรับได้จากใคร/ช่องทางไหน—
4ต้องขอสิทธิ์/whitelist อีเมลหรือบัญชีของเจ้าหน้าที่ 2 คนไว้ล่วงหน้าก่อนหรือไม่ (Cloudflare Access มักต้องอนุญาตผู้ใช้ก่อนถึงจะผ่านเข้าได้)—
5ชื่อ container/อิมเมจจริงบน Server B (รันจาก docker compose ps เพื่อยืนยัน)—
แหล่งอ้างอิงของเนื้อหาที่ยืนยันแล้ว

คำสั่ง Docker/health check/งานประจำสัปดาห์ในคู่มือนี้ อ้างอิงจากโค้ดจริงในโปรเจกต์ (docker-compose.prod.yml, โฟลเดอร์ scripts/) และสไลด์ deploy guide ของทีมพัฒนา (17 หน้า) — ส่วนตารางเทียบ Server A/B ในหัวข้อ 1 มาจากสไลด์เดียวกัน หน้าที่เทียบสองเซิร์ฟเวอร์

ไฟล์นี้เป็นฉบับร่างสำหรับวางแผนโฟลว์การอบรม — ต้องเติมข้อมูลในกล่องสีเหลืองให้ครบก่อนใช้สอนจริง ดูสถานะล่าสุดได้ที่หัวข้อ "สถานะของคู่มือนี้"
